# Benchmarking and error measurement

How to produce the numbers a rendering paper needs: error against a
reference, at equal render time, on a fixed scene suite, reproducibly.

## Quick start

```bash
cmake --build build                                   # Raytracer, rt_compare, tests
python3 benchmarks/render_references.py --spp 65536   # once per scene suite / renderer change
python3 benchmarks/run_benchmarks.py --time 60 --repeats 3
python3 benchmarks/plot_convergence.py benchmarks/results/<run>   # needs matplotlib
```

References live in `benchmarks/references/` and are not committed (they are
large and regenerable). Each results run copies their metadata into its
`run.json`. `run_benchmarks.py` prints where it wrote its results. Each run directory holds
per-pass CSV logs, final images, `summary.csv`, `run.json` (commit, machine,
settings) and, after plotting, `plots/` with figures and a markdown table.

## The pieces

| Piece | What it does |
|---|---|
| `Raytracer --time-budget S` | Progressive rendering for S seconds of render time |
| `Raytracer --reference R.pfm --ref-variance V.pfm --log L.csv` | Error after every pass |
| `Raytracer --variance-out V.pfm` | Per-pixel variance of the mean |
| `rt_compare test.pfm ref.pfm` | MSE / relMSE / MAPE / FLIP of any two images, `--json`, `--flip-map` |
| `benchmarks/make_scenes.py` | Generates the scene suite |
| `benchmarks/render_references.py` | References with their own seed and metadata |
| `benchmarks/run_benchmarks.py` | Equal-time sweeps over scenes x methods x seeds |
| `benchmarks/plot_convergence.py` | Error-vs-time figures and a summary table |
| `tools/validate_flip.sh` | Checks the FLIP integration against NVIDIA's published values |

## Metrics

Averaged over pixels and the three color channels, with `t` the test image
and `r` the reference:

| Metric | Definition | Notes |
|---|---|---|
| MSE | mean (t − r)² | |
| relMSE | mean (t − r)² / (r² + 0.01) | the standard Monte Carlo rendering metric (Rousselle et al. 2011) |
| MAPE | mean \|t − r\| / (r + 0.01) | |
| HDR-FLIP | NVIDIA FLIP on HDR input, mean error in [0, 1] | perceptual; exposure range taken from the reference |

FLIP is NVIDIA's reference implementation (`src/3rdParty/flip`, BSD-3,
unmodified). `tools/validate_flip.sh` reproduces the values published in
NVIDIA's own test suite: LDR-FLIP 0.159693 and HDR-FLIP 0.283547, both exact.

### Reference noise correction

A reference rendered with N samples is itself noisy. With test image t and
reference r independent and unbiased,
E[(t − r)²] = E[(t − μ)²] + Var(r), so measured error has a floor.
`--ref-variance` (or `rt_compare --ref-variance`) subtracts the reference's
per-pixel variance of the mean; logs report both raw and corrected values.
Corrected values at or below zero mean "error below the reference's noise
floor": render a better reference.

## Protocol

**Seeds.** A test render must never share random streams with its
reference. Each sample's stream depends only on (pixel, sample index, seed),
so a test with the reference's seed repeats the reference's first samples,
and its error falls faster than 1/N. References use seed 1000003; test runs
use seeds 1..999. `run_benchmarks.py` refuses a collision.

**Equal time.** Passes double the sample count (1, 1, 2, 4, ... spp); with a
budget, the final passes shrink to fit it, based on the measured cost per
sample. Only rendering is timed. Scene loading, BVH construction and metric
evaluation are excluded. Overshoot depends on how well the previous pass
predicts the next one's cost; in practice it is a few milliseconds (a 2 s
budget ends at 2.001 s).

**Determinism.** A render is bit-identical for any thread count, tile size
or pass split (tested). Two runs that differ only in method therefore differ
only in the method.

**Fair timing.** Run on an otherwise idle machine, keep `--threads` fixed,
and report the machine (`run.json` records CPU, core count and commit).
Repeat with several seeds (`--repeats`). The plots show the geometric mean
across seeds.

**References.** A reference is an estimate, not ground truth. Render
references with as many samples as the hardware allows, and at least an
order of magnitude more than any test run. `glass_caustic` converges slowly
for a unidirectional path tracer, and its reference stays noisy at any
practical sample count. Treat its numbers as relative.

## Scene suite

Generated by `benchmarks/make_scenes.py` into `benchmarks/scenes/`.

| Scene | Tests | Resolution |
|---|---|---|
| `cornell_box` | diffuse interreflection, small area light | 256² |
| `cornell_glossy` | glossy floor, rough copper, glass (MIS + caustics) | 256² |
| `veach_mis` | Veach's four plates x four lights of equal power | 384x256 |
| `glass_caustic` | a glass sphere focusing a small light | 256² |
| `env_objects` | four materials under an HDR sky with a 1° sun (`benchmarks/env/sunsky.hdr`) | 320x240 |
| `sun_sky_bunny` | 144k-triangle mesh, analytic sun + sky | 320x240 |

`benchmarks/make_sunsky_hdr.py` writes the HDR sky: a gradient sky, darker
ground, and a small sun delivering most of the irradiance.

**Check where the error comes from before trusting a ranking.** The first
benchmark run had NEE 7-110x worse than MIS on the diffuse Cornell box, with
a 15x spread between seeds. Five pixels carried 98.7% of the error: rare
fireflies from paths entering the 1 mm gap between the ceiling and a
*two-sided* light, where light sampling sees the emitter's back at almost
zero distance. Real Cornell box lights emit downward only. With a one-sided
light (`<TwoSided value="0"/>` on an `Emissive` material), NEE and MIS give
the same variance, as theory predicts for a diffuse scene. The scene design
was wrong, not the integrator.

## Adding a method

Add an entry to `METHODS` in `benchmarks/run_benchmarks.py` mapping a label
to renderer flags, and give it a color slot in `METHOD_STYLE` in
`plot_convergence.py`. The existing labels keep their colors.

## Regression testing

`ctest` includes a statistical regression test
(`statistical_regression_against_stored_references` in `tests/test_eval.cpp`).
It renders `cornell_box` and `veach_mis` at 48 px width with 2048 spp and
compares them with stored 65536-spp references (`tests/data/`), in units of
standard error:

- per-channel global bias z;
- median block z² over 4x4-pixel blocks;
- fraction of blocks beyond |z| = 3.29.

Variances are derived from the reference, and channels are tested
separately. Pooling correlated R, G and B as independent, or using the
test's own variance estimate, made the statistics overdispersed (measured
over 20 seeds). The thresholds are set from the measured null distribution.
Mutation checks confirm the test fails for emitters 1% too bright and for a
broken MIS weight. A 10% change in GGX roughness fails only narrowly: subtle
material changes are covered by the BSDF unit tests.

If the expected image changes on purpose, regenerate with
`tests/data/make_regression_refs.sh` and say so in the commit message.
